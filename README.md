# dsh-model-failover

DeepSeek Harness 模型故障切换插件。当前模型请求失败时，插件按配置寻找其他服务商的备用模型，在**同一个会话**里接着回答，不用重新发送问题或新建会话。

> **隐私提醒：**切换后，Harness 会把续作所需的会话历史、断流前已输出的可见回复草稿和续作提示发给备用服务商。只添加你信任、且允许接收这些内容的服务商。

## 安装与卸载

插件针对 DeepSeek Harness `0.2.2-rc.5` 开发，插件清单声明的兼容范围为 `>=0.2.2-rc.5 <0.3.0`。先在 Harness 的「模型」设置中配置至少两个服务商，确认各自的模型可用。

1. 克隆仓库：

   ```sh
   git clone https://github.com/HUanyu2609-111/dsh-model-failover.git
   ```

2. 将插件添加到桌面版使用的 `desktop` profile。把示例路径替换为克隆后插件目录的实际绝对路径：

   ```sh
   dsh plugin --profile desktop add "D:/projects/dsh-model-failover"
   ```

3. 重启 Harness 或重新载入对应 profile，然后打开 **设置 → 模型故障切换**。如果你运行的是自定义 CLI profile，把命令中的 `desktop` 换成实际使用的 profile 名。

卸载时使用安装时的 profile：

```sh
dsh plugin --profile desktop remove dsh-model-failover
```

## 配置备用模型

1. 确认已勾选「启用自动切换」。插件默认启用，但备用列表默认为空。
2. 从模型目录添加与当前模型**不同服务商**的备用模型。使用「上移」「下移」调整顺序，列表越靠上优先级越高。
3. 每条备用模型可单独设置「推理等级」。保留「跟随模型默认」可使用目标模型当前的默认等级；也可以选择该模型声明支持的等级。
4. 点击「保存」。模型目录暂不可用时，已保存的选项不会丢失；可点击「刷新模型」重新读取目录。

## 故障切换流程

1. **接收请求错误。** 插件监听 Harness 的 `agent/request-error` 事件。配额用尽、限流、网络错误、上游断流等错误通常在第一次失败时就尝试切换；`TIMEOUT` 要连续出现 **6 次**（包括首次请求），前 5 次由 Harness 的原生重试策略处理。如果原生策略提前结束请求，就不会达到切换阈值。
2. **选出备用模型。** 按保存的优先级查找，跳过本轮故障过程中已尝试过的服务商、目录中不存在的模型，以及调用配置无效的模型（例如保存的推理等级已停用）。上下文窗口超限和图片需要转存时，先让 Harness 尝试原生修复。
3. **等待失败轮次结束。** 找到候选后，插件等当前轮次以相应错误结束，并等 Agent 空闲；随后再检查插件开关、备用配置、会话的模型选择和输入队列。手动切模型、排队的新输入和取消请求优先，不会被自动续跑覆盖。
4. **切换并接续。** 插件修改当前会话的模型选择，并发送一条续作提示来开启新轮次。备用模型沿用会话历史、原始问题和已记录的工具结果。如果失败轮次留下了可见回复，续作提示会附上最近一份未完成的回复草稿，提醒备用模型从已有进度继续，并先核实结果不确定的操作。
5. **继续或结束。** 备用也失败时，从尚未尝试的服务商中继续按顺序选择，不在已尝试的服务商之间来回切换。没有候选时，回到 Harness 的原生重试或报错流程。恢复成功后，会话保持切换后的模型；插件不会自动切回原模型。

插件只处理 Harness 收到的模型请求错误。手动停止、单纯的界面断线或重新连接，不会触发切换。

## 开发与验证

在插件目录运行以下命令。完整测试使用 Node.js 的 `registerHooks`，需要 Node.js **22.15+** 或 **24 LTS**，并能安装清单中声明的 Harness SDK 依赖：

```sh
npm install
node test.js
```

测试使用内存会话和模拟服务商，不访问真实模型 API，也不修改用户 profile。覆盖连续超时阈值、无可用候选、推理等级失效、断流续跑、手动停止及防止重复切换等情形。如果依赖不在本地 `node_modules`，也可将 `DSH_SDK_ANCHOR` 指向兼容的 Harness SDK 所在的 `package.json`；Windows 桌面安装包里的 SDK 需要用自带的 Electron Node 运行时读取。

在 Windows Git Bash 下，如果桌面 profile 已配置默认模型及**恰好两个**备用模型，且三者属于不同服务商，可运行本地 HTTP 探针：

```sh
DSH_FAILOVER_LIVE=0 bash ./failover-http-probe.sh
```

探针读取现有配置，但不修改它；默认只请求本机模拟服务，检查第一个备用正常、以及第一个备用也超时时的接续行为。安装目录不是默认位置时，设置 `DSH_FAILOVER_RUNTIME_DIR`。不要随意启用 `DSH_FAILOVER_LIVE=1`，它会向已配置的备用服务商发送测试请求，可能产生费用。

## 常见问题

- **找不到设置页：**确认插件安装在当前 profile，并在安装后重新载入。桌面版默认是 `desktop`。
- **超时后没有切换：**确认开关已打开、至少有一个可用的跨服务商备用，以及 Harness 重试策略能让当前模型尝试满 6 次。
- **某个备用模型被跳过：**刷新模型目录，检查模型是否还可用。如果推理等级已失效，改回「跟随模型默认」或选择仍受支持的等级，再保存。
